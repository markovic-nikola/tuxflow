TuxFlow
Remote projects Agents Install GitHub

Dev servers, agents and terminals in one window.

TuxFlow is a Linux desktop app that runs everything a project needs side by side. The project can live on this machine, or on a server over SSH, where it keeps running after you close the lid.

Install TuxFlow See the latest release

The same window, wherever the project lives

The sidebar colours a project by where it runs, so you never restart the wrong server. Everything below works the same way in both.

On this machine

A real terminal per process
Start, stop and restart each dev server, worker and shell on its own. Output stays when a process stops, so the last run is still there to read.
Restarts after a crash
A crashed process comes back with exponential backoff, and stops retrying after repeated failures so you can fix the cause.
Restarts when files change
Give a process glob patterns to watch and it restarts when a matching file is saved.
Opens the right URL
TuxFlow reads the address a dev server prints, ignores build-tool noise, and opens the browser once the server answers.

On a server, over SSH

Processes outlive the connection
Each one runs in a tmux session on the host. A dropped connection or quitting TuxFlow only detaches. It reattaches the next time you open the project.
Ports come to localhost
TuxFlow asks the host what a run is listening on and forwards every port, so the browser button opens the remote app.
Clipboard and files cross over
Select text in a remote terminal and it is on your clipboard. Paste a screenshot or drop a file and it uploads to the host, with the path typed for you.
Your microphone, their agent
Hold to talk to an agent running on the server. The recording comes from this machine over the same SSH connection.
Editor and git follow
The editor button opens the project on the host, and the git view works over SSH.

Needs ssh here and tmux on the host. Without tmux, processes still run but stop with the connection.

Agents sit next to the servers they work on

Add Claude Code, Codex, Gemini CLI, OpenCode, Aider or any other command as an agent. Each gets a row in the sidebar that shows when it is working.

Know when a turn ends
A desktop notification and a sound per agent when one finishes and waits for you. Nothing fires for the terminal you are looking at.
Write without lag
A message box under the terminal takes your prompt locally and sends it on Enter. Pasted images go along as attachments.
Let the agent read your logs
An MCP server lets agents list processes, read their output, and start, stop or restart them.
claude mcp add --scope user tuxflow -- tuxflow-mcp

Codex, Gemini CLI and Amp have the same one-line setup under Settings, Integrations.

Review and commit without leaving

The status bar shows the branch, how far it is ahead or behind, and the lines changed. One click fetches, pulls and pushes.

Open the changes to read a diff with the edited words marked inside each line, then commit and push from the same view.

The rest of it

Finds your commands
Detects Node.js, Rust, Go, Python, PHP and Laravel, and Docker projects and offers their usual commands when you add one.
Many projects, one sidebar
Drag to reorder, sort by most recently used, and filter by name.
A proper terminal
True colour, mouse support, scrollback search, clickable URLs and 46 colour schemes.
SSH connections
Hosts from ~/.ssh/config open as terminals that reconnect on their own.
Looks like your desktop
Dark, light or follow the system, with accent colours you pick.
Picks up where you left off
Open projects, process order and window position come back on the next launch.
Everything from the keyboard
The command palette reaches every action, process and project.
Updates itself
New releases arrive through apt, or from the status bar in the app.

Configuration lives in the app. If you would rather keep it in the repository, add a tuxflow.toml:

[project]
name = "storefront"

[[process]]
name = "dev"
command = "npm run dev"
start_with_project = true
auto_restart = true
open_in_browser = true

[[process]]
name = "claude"
command = "claude"
category = "agent"

Install

For x86_64 Linux, on X11 or Wayland. The binary needs no desktop toolkit.

curl -fsSL https://markovic-nikola.github.io/tuxflow/KEY.gpg \
  | sudo gpg --dearmor -o /usr/share/keyrings/tuxflow.gpg

echo "deb [signed-by=/usr/share/keyrings/tuxflow.gpg] \
https://markovic-nikola.github.io/tuxflow stable main" \
  | sudo tee /etc/apt/sources.list.d/tuxflow.list

sudo apt update && sudo apt install tuxflow

For Debian and Ubuntu. New releases then arrive with apt upgrade.

sudo apt install ./tuxflow_*_amd64.deb

Download the .deb from the latest release first. The app offers later releases from its status bar.

tar xzf tuxflow-*-x86_64-linux.tar.gz
cd tuxflow-*-x86_64-linux
./install.sh --user

Download the .tar.gz from the latest release first. --user installs to ~/.local. Without it the script installs to /usr/local and asks for sudo.

git clone https://github.com/markovic-nikola/tuxflow.git
cd tuxflow
cargo build --release -p tuxflow
./target/release/tuxflow

Needs a Rust toolchain and a C compiler (build-essential, gcc or base-devel). No toolkit development packages.
